# タスクと状態ファイルの運用ルール

## 構成
```
tasks/
├── INDEX.md               # 親タスクの一覧（1行1件）
├── _templates/            # STATE.md・子タスクファイル・log の型
├── Txx_名前/
│   ├── STATE.md           # 親の状態：目的・完了条件・子タスクの表
│   ├── Txx-n_名前.md      # 子タスクの状態
│   └── log/               # 経緯・試行錯誤（普段はAIに読ませない）
└── _done/                 # 完了した親タスクをフォルダごと移す
```

## ID と命名
- 親タスク：`T01`, `T02` …（2桁、連番。欠番は再利用しない）
- 子タスク：`T02-1`, `T02-2` …
- フォルダ名・ファイル名は `ID_短い日本語名`

## INDEX.md
- 1行1件。列は `ID / 名前 / 状態 / 次の一手`
- 状態は `未着手 / 進行中 / 保留 / 完了` のいずれか
- 親タスクの状態や次の一手が変わったら、その場で更新する

## 状態ファイル（STATE.md・子タスクファイル）
- 型は `tasks/_templates/` に従う。見出しを削らない（該当なしなら「なし」と書く）
- **上書きして常に最新だけにする**。経緯は書かない
- 「決めたこと」は台帳のIDと1行だけ。本文は `docs/decisions.md`
- 「済んだこと」は成果物のパス付きで書く
- 「やめたこと・採らなかった案と理由」は省略しない。同じ案の再提案を防ぐための項目
- 「未決・保留」は誰が・いつ決めるかを添える
- 「次の一手」は最初にやることを1つだけ
- 冒頭の `（更新：YYYY-MM-DD）` を更新のたびに直す

## log/
- `log/YYYY-MM-DD.md` に追記する（同日は同じファイルに追記）
- 試した手順、エラー、議論の経緯など、状態ファイルに書かない情報を置く
- 普段は読まない。状態ファイルだけで判断できないときに参照する

## 決定台帳（docs/decisions.md）
- **決めた時点で追記する**。会話の終わりにまとめて書かない
- 1行1決定。列は `ID / 日付 / 決定（1文） / 理由 / 出典 / 状態`
- 状態は `有効 / 仮 / D-xxxで変更 / 廃止`。過去の行は消さず、状態列だけ更新する
- 決定を変えるときは新しい行を追加し、旧行の状態を `D-xxxで変更` にする
- 選択肢の比較が必要な重い判断は ADR（`docs/adr/`）も書き、出典に ADR 番号を入れる

## 完了したら
- 子タスク：親の STATE.md の子タスク表で状態を `完了` にする
- 親タスク：INDEX.md の状態を `完了` にし、フォルダを `tasks/_done/` に移す

## 外部の課題管理との関係
- GitHub Issues などで課題管理を始めたら、**課題の正本はそちら**に置き、`tasks/` にはAIの作業状態だけを書く
- その時点でこのファイルを更新する

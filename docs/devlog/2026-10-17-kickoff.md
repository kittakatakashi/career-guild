# 2026-10-17 キックオフ：状況把握とロードマップ作成

- フェーズ: Phase 0
- 環境: リモート（スマホから Remote Control）
- 関連実験: なし

## 頼んだこと
- フォルダ内の資料（要件定義書、企画段階の議論まとめ）を読んで状況を把握する
- Obsidian に保存していたプロトタイプを探して持ってくる
- ロードマップの進め方を相談し、ドラフトを作る
- Phase 0 の立ち上げ（git、ディレクトリ構成、CLAUDE.md、ADR/devlog の型）

## Claude の動き
- 資料を読んで、議論メモが参照しているプロトタイプと引き継ぎ資料がフォルダにないことを指摘した
- プロトタイプは場所（vault 内のフォルダ名）を伝えるだけで発見できた
- 進め方として「痛み駆動」をまず提案 → 一人開発では痛みが出にくいという指摘を受けて「Before/After 比較実験型」に修正した
- 公開リポジトリにする前提で、議論メモ（個人情報を含む）とプロトタイプの実名を除外するよう先回りで指摘した

## 詰まったところ・気づき
- ホームディレクトリ全体への `find` はタイムアウト。macOS では Spotlight（`mdfind`）の方が速い
- 親ディレクトリ（`~/Develop/CLAUDE.md`）の共通ルール（diff 提示、テスト必須など）もこのプロジェクトに効いている。CLAUDE.md の階層構造は講義ネタになる
- 「一人だと痛みを感じにくい」は、ガードレールを講義で語るうえでの本質的な課題。比較実験という型に落とせたのは収穫

## ルール・設定に足したこと
- `CLAUDE.md`：最小構成（Phase 1 の Before 観察のため、あえて薄く）
- `.claude/settings.json`：`.env*` と `private/` の読み取りを deny
- `.gitignore`：`private/`、`.env*` など

## 講義・ブログで使えそうなネタ
- 「痛み駆動」ではなく「比較実験」でガードレールを入れる、という考え方
- 公開リポジトリ前提のときに、最初から入れるべき最低限のガードレール
- スマホからのリモートセッションだけでプロジェクトを立ち上げた話

# ADR-0003: Before/After 比較実験を MVP 完成後に回す

- 日付: 2026-10-18
- ステータス: 承認（ADR-0001 の適用時期を変更）。「必要になった分だけ足す」の部分は D-007（2026-10-23）で変更：既知の工夫はベースとして最初から入れる

## 背景
ADR-0001 では、ガードレールや自動化の仕組みを Before/After の比較実験で導入する方針とし、ロードマップ v0.1 では Phase 1（MVP）に E1〜E4 の実験を組み込んでいた。
しかし Phase 1 にはプロダクト機能・試用者テスト・比較実験が重なっており、実験の設計（お題の固定、観察項目の定義）を先にやると MVP の着手が遅れる。

## 選択肢
- A: ロードマップ v0.1 どおり、Phase 1 で E1〜E4 を実施する
- B: 比較実験は MVP 完成後に回し、MVP は普通に作る
- C: 比較実験をやめる

## 決定
B を選ぶ。MVP 中は必要になった分だけ CLAUDE.md・permissions・hooks を足し、足した理由を devlog に残す。E1〜E4 の実施時期は Phase 1 完了時に決める。

## 理由
- A は走り出しが遅くなる。まず動くものを作るほうが、プロジェクト全体の進みが速い
- C は ADR-0001 の目的（「入れたらこう変わった」を語れること）を捨てることになる
- B なら MVP 中に起きた困りごとが記録として残り、後の実験のお題・観察項目の材料になる

## 影響
- Phase 1 の成果物から「E1〜E4 の Before/After 記録」が外れる
- MVP 中に仕組みを足すと「素の状態」の観察機会は減る。後の実験は、MVP 後の新機能を題材にしてやり直す前提とする
- シークレット防止・個人情報の除外は引き続き最初から適用する（ADR-0001・0002 のまま）

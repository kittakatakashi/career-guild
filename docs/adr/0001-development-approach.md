# ADR-0001: 開発の進め方（比較実験型で仕組みを導入する）

- 日付: 2026-10-17
- ステータス: 承認（適用時期を ADR-0003 で変更）

## 背景
このプロジェクトの主目的は、Claude Code によるAI駆動開発（特にガードレール設計と自動化）を、企業のエンジニア向けに実体験として語れるようになること。
ガードレールや自動化を最初から全部入れると「なぜ必要か」を体験できない。一方、一人開発では「なかったせいで困った」という痛みが自然には発生しにくい。

## 選択肢
- A: 最初から本格的な構成（CI、hooks、サブエージェント等）を全部入れる
- B: 痛みが発生してから導入する
- C: 仕組みなしの状態を意図的に観察し（Before）、導入後と比較する（After）

## 決定
C を基本とし、ロードマップは「プロダクト／ガードレール／自動化・CI/CD／教材化」の軸で組む。
ただしシークレット防止と個人情報の除外は最初から入れる。

## 理由
- A は導入理由を体験できず、講義の説得力が出ない
- B は一人開発では痛みが起きにくく、待っていても体験できない可能性が高い
- C なら一人でも再現でき、「入れたらこう変わった」を比較として示せる

## 影響
- 各実験の Before/After を `docs/devlog/` に記録する運用コストが発生する
- Phase 1 の CLAUDE.md はあえて薄い状態から始める

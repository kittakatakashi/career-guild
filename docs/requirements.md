# 要件定義書：経歴書RPG（仮称）

最終更新: 2026-10-18 / ステータス: ドラフト v0.2（ロードマップ v0.1 との整合を反映）

## 1. プロダクト概要

### 1.1 コンセプト
職務経歴書をRPGのキャラクターステータス画面のように可視化するWebアプリ。
AIが経歴書を解析してスキルパラメーターをスコアリングし、ゲーム感覚で自分のキャリアを客観視できる体験を提供する。

### 1.2 提供価値の核
**「自分の経歴を初めて客観スコアで見る面白さ」**
書き方アドバイスやクエスト生成などは後続フェーズ。MVPはこの体験単体で成立させる。

### 1.3 ターゲットユーザー
副業を始めたい会社員。自分の市場価値を可視化したいが、転職サイトの診断ツールはお堅すぎて続かない層。

## 3. 機能要件（Phase 1）

### 3.1 画面フロー

```
[入力画面]
  ├ テキスト入力欄
  ├ ファイルアップロード（PDF/docx）
  ├ プライバシー表記
  └ 「査定開始」ボタン
       ↓
[ローディング画面]
  └ RPG風演出（「冒険者ギルドが経歴を査定中…」など）
       ↓
[結果画面]
  └ RPGステータス画面（キャラ名・職業・各スキルパラメーター・根拠コメント）
```

### 3.2 入力機能

- **対応形式**：プレーンテキスト、PDF、docx
- **テキスト**：テキストエリアへの直接貼り付け
- **ファイル**：ドラッグ&ドロップ または ファイル選択
- **想定ライブラリ**：PDF解析に `pdf.js`、docx解析に `mammoth.js`
- **文字数上限**：要検討（現行の Flash 系モデルのコンテキストには十分収まるため、UX観点で5万字程度の上限が妥当）

### 3.3 AI解析機能

- **使用API**：Google Gemini API。モデルは着手前に選定（5.1 参照）
- **API呼び出し**：フロントエンドから直接呼び出し（バックエンド不要）
- **APIキー管理**：MVPフェーズでは環境変数（`.env`）で管理
  - ⚠️ 注意：フロントエンドから直接APIを叩く場合、APIキーが露出する。MVP はローカル／保護付きプレビューに限定し、一般公開は Phase 2 のサーバー経由化の後に行う。
- **入力データの扱い**：5.2 参照（無料枠では入力が Google の製品改善に使われうる）

#### 3.3.1 スコアリング方式（方針案）

**「判定はAI、計算は機械」**とする。AIにスコアを直接出させると、同じ経歴書でも実行のたびに点数がぶれ、「客観スコア」という提供価値（1.2）が崩れるため。

- **構造**：スキル項目（例：PM経験、提案力、技術力…）ごとに、レベル順に並んだチェック項目（判定基準）を持つ
  - 例：PM経験
    - Lv1：プロジェクトのメンバーとして進捗管理に関わった経験がある
    - Lv2：小規模（数名）のチームでリーダーを務めた経験がある
    - Lv3：予算・スケジュール・品質の責任を持ってプロジェクトを完遂した経験がある
    - Lv4：複数チーム／ベンダーを束ねた経験がある
    - Lv5：PMとして組織の標準化・後進育成に関わった経験がある（＝プロフェッショナル）
  - （上記は構造を示すための仮置き。中身は 7 の「スキル軸・判定基準の定義」で決める）
- **AIの役割**：各チェック項目について「経歴書にその経験の記述があるか」を true/false で判定し、**根拠となる経歴書中の記述を引用**して返す
- **機械（コード）の役割**：判定結果からレベル・スコアを計算する（加算ロジック・上限・総合スコア算出はコード側で決定的に行う）
- **根拠の表示**：結果画面で「なぜこのレベルか」を引用付きで表示できるようにする
- **再現性の確保策**：
  - 構造化出力（JSONスキーマ指定）を使い、出力形式を固定する
  - temperature 等の生成パラメータを低く固定する
  - 判定基準は「経験の有無」で答えられる粒度に分解する（「優秀か」のような主観判定を入れない）
- **参考にする考え方**：タレントマネジメントのスキルチェック／スキルマップ（ITSS・iCD のレベル定義など）を、経歴書から自動で埋めるイメージ
- **未決**：レベル判定のルール（下位レベル未達でも上位を満たせば認めるか）、総合スコアの算出式、RPG表示用の数値（0-100等）への変換

- **出力形式**：JSON（構造化出力のスキーマで指定する）

### 3.4 表示機能

- **画面構成**：本プロジェクトのプロトタイプ（`docs/prototype/resume-rpg.tsx`）をベースに実装
- **タブ構成**：
  - ステータス（レーダーチャート＋各スキルバー＋装備欄）
  - スキル（個別スキルの詳細とランク）
  - クエスト（Phase 3で実装。MVPでは空または将来予告として表示）
- **アニメーション**：スキルバーが0から各値まで伸びるアニメーション

### 3.5 ローディング演出

- **コンセプト**：「冒険者ギルドが経歴を査定中…」
- **演出要素**：
  - 査定進行を示すテキスト（複数パターンを順に切り替え）
    - 例：「ギルドマスターが書類を確認中…」「スキル鑑定士が能力値を測定中…」「魔導書に記録中…」
  - プログレスバーまたはアニメーション
  - 効果音は不要（MVPでは）

### 3.6 エラー処理

- **方針**：シンプル表示、自動リトライなし
- **対象エラー**：
  - Gemini APIが想定外のJSONを返した場合
  - APIレート制限に達した場合
  - ネットワークエラー
  - ファイルパース失敗
- **UI**：「もう一度お試しください」のシンプルなエラーメッセージ表示

### 3.7 プライバシー表記

- **表示位置**：入力欄の直下
- **文言案**：
  > 入力された経歴情報はGoogle Gemini APIに送信されます。本サービスでは情報の保存・記録は行いません。
- ⚠️ 上記文言は**有料枠を使う場合のみ成立**する。無料枠では Google が入力を製品改善に使いうるため、他人に使ってもらう段階では有料枠への切替か、文言の修正が必要（5.2 参照）

## 4. 非機能要件

### 4.1 技術スタック

| レイヤー | 技術 |

| フロントエンド | React（Vite + TypeScript + Vitest を想定。着手前に ADR で確定） |

### 4.3 ブラウザ対応

- 最新のChrome / Safari / Edge / Firefox

### 4.4 パフォーマンス

- 初回ロード3秒以内
- API応答時間はGemini側依存（数秒〜十数秒を想定）

## 5. 制約・前提

### 5.1 Gemini API のモデルと料金（2026-10-18 時点、公式料金ページ 2026-10-16 更新版より）

| モデル | 無料枠 | 有料枠（入力 / 出力、1Mトークンあたり） |
|---|---|---|
| Gemini 3.8 Flash | あり | $0.75 / $3.75（2027-01-01 から $1.50 / $7.50） |
| Gemini 3.6 Flash | あり | $0.75 / $3.75（同上） |
| Gemini 3.5 Flash-Lite | あり | $0.30 / $2.50 |
| Gemini 3.1 Flash-Lite | あり | $0.25 / $1.50 |
| Gemini 2.5 Flash | あり | $0.30 / $2.50 |
| Gemini 2.5 Flash-Lite | あり | $0.10 / $0.40 |

- **レート制限**：公式ドキュメントには数値の記載がなく、AI Studio のレート制限ページで確認する方式に変わっている（プロジェクト単位、RPD は太平洋時間0時リセット）。第三者情報では数値が割れているため、着手時に AI Studio で実値を確認する
- **1回あたりの概算コスト（有料枠）**：経歴書 約1万トークン入力・約2千トークン出力として、2.5 Flash で約 $0.01、3.8 Flash でも約 $0.015。検証規模なら有料枠でも費用はほぼ問題にならない
- 出典：[Gemini API Pricing](https://ai.google.dev/gemini-api/docs/pricing)、[Rate limits](https://ai.google.dev/gemini-api/docs/rate-limits)

### 5.2 入力データの扱い（プライバシー）

- **無料枠**：入力・出力が Google の製品改善に使われる（"Content used to improve our products"）。人間のレビュアーが読む可能性もある。AI Studio 上での利用は課金設定があっても無料枠扱い
- **有料枠**：入力・出力は製品改善に使われない
- **方針**：
  - 開発中は**自分のサンプル（架空化したもの、または自分で許容できる範囲のもの）だけ**で無料枠を使う
  - 他人の経歴書を扱う段階（MVPの試用者テスト以降）では有料枠に切り替える。他社APIを使う場合も、学習に使われない条件（API利用・有料プラン等）を確認する
- 実在の経歴書データはリポジトリに入れない（ADR-0002）

### 5.3 APIキーセキュリティ

- フロントエンド直接呼び出しの構成上、APIキーが露出する
- MVP は一般公開しない。公開時はサーバー経由（Phase 2）に変更必須

### 5.4 データ保存なし

- ユーザーの経歴情報はサーバー側で一切保存しない
- 結果画面を閉じるとデータは消える（ユーザーがスクショ等で保存する想定）
